# 27 October 2026: the row's view and notes (core step 3b)

A row has one view, drawn in the side panel and, with Open full, as its own page at `#/row/<id>`
in the record layout, with its module and table as the way back: fields, notes, its parts (step
3a) as small tables with New (the new row comes with this one given), "Linked here" (the rows of
other tables whose relation points at it, and the notes that mention it), what its values were read
from, tasks and documents. The core serves a row on its own (`/api/rows/:row`) and what is around
it (`/api/rows/:row/around`); links are the relations rows already hold and mentions are found in
the notes themselves (`instr`), so nothing is stored to keep in step. A new field kind, `notes`
(kit API, connector SDK and the core alike): Markdown with a person or a row mentioned as a link,
one per table, kept like any value (versions, provenance, undo, the trash, Find), hidden from the
grid and from the model's table views and read in a view of its own, `row_notes` (not `notes`,
which Network's Notes table already has). The builder gives each main table it makes a Notes field;
a part or a setup table gets none. In the window, Write opens a plain text box, @ and a few letters
offer people and rows from ⌘K's finder, and it saves on leaving the box. A person's page lists the
notes that mention them, under a merged id too. A set of notes is journaled as "Wrote the notes on
…", not the whole text. Journey `a-note-on-a-row` passed first time.
