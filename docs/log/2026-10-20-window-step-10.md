## Room

- **The cause, besides the proposal's centred columns:** the window's root text is 14px and
  Tailwind's spacing step is 0.25rem, so every size translated from the mock's pixels came out
  12.5% small (rail 189px, bar 42px, side panel 280px, stream 686px). The step is now 4px in
  `app.css` (`--spacing`), and the few rem values in grid columns are the mock's pixels.
- **Widths as tokens:** `max-w-stream` (784px: 720px of text in 32px gutters), `max-w-page`
  (1200px), and a `wide` utility: a stream table whose natural width is more than the text's
  runs up to 960px, centred on the text (`ui/words.tsx` measures it).
- Settings, Activity and Agents and notes fill the window up to 1200px; connections are tiles;
  agents and notes sit side by side on a wide page.

## Today

  finish, and each clock agent's next run (`nextRun` in `modules/agents.ts`, the runner's rule).
  `POST /api/today/seen` clears. Cards and running runs carry their module for the lens.
- `Today.tsx`: Needs you (cards and sign-ins, each going to its place), Running (with Stop),

- First tried: "last looked" moved on each window load. A reload or a screenshot run then

## Tables like v1

v1's table page (alpha-brain `DataPage`, `views/engine.ts`, `world/views.py`) read first; rewritten.

- **Saved views** (`world/views.ts`, migration 6): per table, shared, journaled (kind `view`, not
  in the stream), kept by field id and given by name, name or slug; a board gets its first choice
  and a calendar its first date when none is named (v1 refused such a save). module.yaml mirrors
  them by name, with only the parts that say something. Kits bring views (`views:` under a
  table); an update replaces a kit's view while its hash is unchanged. Alpha's `shape` tool has
  `save_view` (a change names only what changes) and `remove_view`. Routes:
  `POST /api/tables/:id/views`, `PUT` and `DELETE /api/views/:id`.
- **The window** (`window/src/table/`): `engine.ts` (search, filters by kind with all or any,
  sorts with empty last, groups, totals, colours; tested), `edits.ts`, `ViewTabs`, `Toolbar`
  (chips for each filter, the sorts and the group; Filter; Columns), `ColumnMenu` (sort, filter,
  group, total, colour, move, hide), `Grid` (TanStack Virtual, sticky header, ticks and name
  column, resize by the edge, shift-click sorts, groups that fold, totals in the foot),
  `RowPanel`, `Many` (ticked rows and a paste awaiting yes). What is not saved stays per table in
  the browser session.
- **Editing:** a value changed in place (double-click, Enter, F2) is a `set` line and the value's
  stated source; ticked rows take one value (`POST /rows/many`) or are removed after the person's
  yes (`POST /rows/remove`, the journal keeps them); a pasted block fills across and down from
  the clicked cell and adds rows past the last, after a yes; Export (`POST /export`, SheetJS in
  connector-files) gives exactly what is shown; + adds a field.
- Found on the way: WebKit does not focus a button on a click, so a cell focuses itself (Enter, F2
  and a paste need it); a first click opens the panel 250ms later so a double-click can edit (the
  panel pushed the cell from under the second click).

Checked: 94 tests (engine, views, kit views, the routes); journeys in WebKit on the test copy and
on a scratch core (port 4720) with made-up deals: sort, filter, group, total, save, change, reload,
board, edit in place, set two rows, remove asked, paste refused then pasted, field added, row

## The other six views

`window/src/table/views/`: list (title and a few values, the view's groups kept), gallery (cards),
calendar (a month on the view's date; a calendar or timeline starts on the date most rows have),
timeline (each row marked on its date along months, today drawn), chart (bars by a group, a
choice keeping all its choices, or by a date's months; rows or the sum of a number, a view's
new `measure`; a bar's click filters the table to its rows), form (a row at a time, Save as
yours, or a new row). `KindPicker` offers each view when the table has what it needs, and what
it goes by. A board's columns and a chart's bars are no longer set as the view's group when the
person only switches to them.
