# 20 October 2026: the rail, modules inside modules

Kenil, 21:00: "i dont want table names to show up on rail, only the module names. Also, modules
should be able to sit within modules … the rail should be collapsible. Also, the side conversation
bar should be expandable". The plan (the Claude Doc "Rail plan: modules only, nested,
collapsible") had his yes at 21:11.

- **Modules inside modules (design §10):** the world's modules gain a parent and who placed it
  (migration 7). `Shape.place` refuses a module inside itself or one of its own and journals each
  move; `module.yaml` says `within:`. A kit's `within:` puts its module there on install, making
  the parent empty when there is none; on update the kit's place stands only while nobody else
  has placed it. Alpha moves modules with `shape`'s `place_module`, and its start layer says which
  module sits inside which. The core lists a module with nothing in sight only when a module
  inside it has something.
- **The window (design §14):** the rail is module names only, each with its modules folded under
  it and a ⋯ menu to move it (Move into…, Top level). It folds to a strip of icons, a module as
  its two letters, with a button or ⌘\. A parent opens on an Overview of its modules as cards;
  the bar shows the path (Shops › Bakery › Orders); Home's modules sit in their parent's card;
  Find opens modules by name; a parent's lens takes in its modules. The Ask panel drags wider up
  to two thirds of the window, expands to half of it, and opens as the full Conversation. The
  rail, its folds and the panel's width are kept per person (`/api/layout`).
- Seen in WebKit, light and dark, on the test copy with the first client's two kits nested by
  their `within:`. Removing a module is not built yet; when it is, the modules inside it move up
  to where it sat.
