# 2 November 2026: the plugin seam (onboarding 4a)

Kenil, 2 Nov 12:02: the whole onboarding flow is an isolated piece, pluggable, not entangled with
the core engine. His yes to the shape at 12:04: what steps 1–3 built stays in the core because it is
not onboarding's (the computer's reader in the platform layer, connectors kept from the model, the
never-use list on a connection; the three connectors are their own package already); onboarding
itself becomes one package in `plugins/`; the core gains one general seam for it.

- `plugin-sdk/`: what a plugin is (`name`, `title`, its own module's folder as `kit`, `register`)
  and the host it gets: the person; the rows of a table a kit or connector keeps, by key; a
  connector's tool as Alpha's own code calls it; one question to the model, no tools, in a schema,
  its cost kept with Alpha's usage under the plugin's module; its own module's rows (proposed as
  assumed with why, changed by the person as stated, journaled); routes under
  `/api/plugins/<name>/`, answered as the person behind the core's token; a block at the start of
  every conversation; a journal line (`kind: 'plugin'`). It imports nothing of the core.
- `core/src/plugins/plugins.ts`: plugins loaded from `plugins/` at start (`PLUGINS_DIR`), checked,
  registered; one that does not load is said and left out; their own modules kept as Alpha's own
  are after Alpha's (`keepKit`, out of `keepDefaults`). The desk's start layer takes the plugins'
  blocks (`DeskOptions.starts`, `startLayer`'s `extra`); the server answers their routes.
- With no `plugins/` folder Alpha runs as before: on Kenil's Alpha, restarted on the branch,
  `/api/plugins/…` is 404 and nothing else changed.
- Tests on a made-up plugin (`core/src/plugins/test-plugin/`): loaded with its module installed,
  its routes (and the token wall), a row proposed then kept, a connector table read by key, its one
  question and its cost under its module, its block in the start layer; a broken one said and left
  out; none adds nothing.
- Its screens in the window come with onboarding's screens (step 6), the same way: built in from
  the package when it is there.
