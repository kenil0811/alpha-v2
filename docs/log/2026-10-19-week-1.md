# 19 October 2026: week 1, the skeleton

Plan agreed with Kenil before building: the desk works in `tenants/<id>/desk/<user>/` and writes
there and in `modules/`; a module's git comes in week 3 with skills and pages; people, facts,
tasks, agents, runs and the skills index wait for the kit that needs them.

## The spikes

Scripts in `spikes/2026-10-19-week-1/` (run from a folder whose `node_modules` links to
`core/node_modules`). The Agent SDK is pinned at 0.3.302, which bundles Claude Code 2.1.302;
pnpm 11 refuses releases younger than a day, so not 0.3.303. All ran on Kenil's subscription on
Haiku, about $0.07 in all by the SDK's own count.

1. **The subscription route:** with no key, no config dir and `PATH=/usr/bin:/bin:/usr/sbin:/sbin`,
   init says `apiKeySource: none` and the turn runs. Each turn brings a `rate_limit_event` with the
   five-hour and seven-day windows, their use and when they reset: the closed-window message has
   what it needs.
2. **In-process tools, strict MCP, no setting sources:** the world tool ran; only the given tools
   are in the session (`tools` sets the base set). Claude Code still fetched Kenil's 15 claude.ai
   connectors in the background (none joined); `ENABLE_CLAUDEAI_MCP_SERVERS=false` stops the
   fetch. Claude Code's bundled skills are listed but unreachable while `Skill` is off.
3. **The callback and the defer:** `canUseTool` allows and denies, and holds a call 150 s while a
   card waits. A PreToolUse `defer` ends the turn with `deferred_tool_use`, but:
   - after a restart Claude Code reruns the deferred call at start-up, before the in-process
     tools are connected, and fails (`tool_deferred_unavailable`), with or without `alwaysLoad` or
     `MCP_CONNECTION_NONBLOCKING=0`;
   - in a live session the deferred call is never rerun; the model retries it and says "the first
     call came back with no result".
   What works, live and after a restart: the gate denies with words saying the call waits on a
   card; the person's yes reaches the desk as a message; the model makes the same call again and
   the gate allows it once because a yes card matches its name and input. Waiting on Kenil's yes,
   since design §7 says "deferred".
   A `break` out of `for await` over a query closes the session: read it with `next()`.
4. **The sandbox:** outside `$TMPDIR` (which every command may write), with
   `denyRead: [home]` and `allowRead` the desk, modules and granted folders: shell writes land in
   the desk and modules only; a granted folder is read, not written; the world file and
   `~/Documents` are neither read nor written; `curl` reaches the callback as
   `SandboxNetworkAccess` with its host. Without `denyRead` the shell reads the whole home.
   Read, Write and Edit go through the callback with their paths (an allow in `allowedTools`
   would skip it).
5. **A background subagent:** the desk's turn ends at once; the outcome arrives as a
   `task_notification` and the desk starts a turn of its own saying it, with no message from the
   person.
6. **Tool search:** needs `ToolSearch` in the base set; out of 60 dummy connector tools the model
   loaded one calendar tool and called it.
7. **Context:** SessionStart fires only after compaction (`source: compact`), never on a fresh
   session, so the start layer goes on the first message of a fresh session; UserPromptSubmit's
   `additionalContext` reaches every turn; PreCompact's `systemMessage` is taken. A resumed session
   keeps its first appended prompt unless `snapshot: false`, which makes an edit to the prompt
   reach the next turn.
8. **Stop:** `interrupt()` ends the turn (`aborted_tools`) and the live session takes the next
   sentence.

`node:sqlite` on this Mac: the step 0 test passes here (WAL, FTS5, backup, read-only, authorizer).

## What was built (uncommitted, for Kenil's review)

- **The world** (`core/src/world/`): one migration; the journal (append-only and never deleted,
  by triggers; FTS5); users with the owner made at first start; modules as directories
  (`module.yaml` mirrored from the world, `NOTES.md`); tables and fields (the eleven kinds);
  records keyed by field id, a version per change, provenance on every value, refused without
  it; removal deleting versions and the index, the journal keeping the values; cards with one
  state, one waiting card per identical call, a yes used once, only a person answers; files by
  hash and documents with places; desk sessions. The model's SQL: temp views per table on a
  read-only connection whose authorizer allows reading those views and nothing else.
- **The engine** (`core/src/engine/`): one long-lived desk per user on the Agent SDK, resumed
  after a restart when the tools match; eight world tools (query, search, shape, write, change,
  file, ask, remember); hooks writing a journal line before and after every call and running the
  gate; the start layer on a fresh session's first message and after compaction; the per-turn
  layer on every message; Stop; a closed usage window said with its time and retried then; a
  background subagent's outcome starting a turn of the desk's own. Config in `core/config/`
  (`system.md`, `models.yaml`, `limits.yaml`), read on use. `system.md` is the design's draft
  less "people" and "tasks" in its first line, since the world holds neither yet.
- **The gates** (`core/src/gates/`): effects mapped to the three gates; a gated call is refused
  with words saying it waits on a card, and the person's yes lets that exact call through once
  (spike 3's finding, agreed by Kenil and now in design §7). The shell's network asks per
  host; a removal the person asked for passes when its words are in their message.
- **The files connector, minimal** (`core/src/files/read.ts`): a dropped file kept and read,
  sheets cell by cell (SheetJS 0.20.3 from its CDN), text by line; `file` reads or imports a
  sheet into a table with each value's cell as its source.
- **The api and the window**: the token, Host and Origin checked on every request; Home as the
  stream (the sentence, one message per turn with the live line, "Show the work", cards inline
  with their buttons, Stop, a file drop); a table view (TanStack Table 9) where every value opens
  to its source; Markdown replies. `pnpm start` builds the window and the core serves it.
- **The journeys runner** (`core/src/journeys/run.ts`, `pnpm journey <name> [--alone]`) and
  `journeys/track-what-i-eat.yaml`.

## What ran for real

- `pnpm check`: typecheck, lint and 34 tests clean (8 files; the desk against a scripted
  session, never the model).
- **The journey, on fresh tenants with Opus** (`docs/journeys/2026-10-19-2039-*`): passed with
  Alpha's prompt appended (23 s) and alone (12 s). A first "alone" run failed only because its
  check wanted the amount to be exactly "2" and the model wrote "2 eggs"; the check was loosened
  and both were run again. Input tokens over the two turns: appended 34k then 106k, alone 30k
  then 61k (cumulative, mostly cache reads). Behaviour the same in both; one run each, so not
  yet a reason to change the design's choice.
- **In the window** (Chromium, the browser pane, on a check home `.data/check`): both sentences;
  "Show the work"; the table view with "You said “log two eggs”" and "Assumed: logged today";
  "remove the eggs, I logged them by mistake" removed it with no card (its words were in the
  message); "run curl … wttr.in" made the card "Let a script reach wttr.in?", Yes carried on and
  gave the weather; the same for example.com with No left it; a dropped CSV imported into Meals
  with each value opening to its cell. Not yet looked at in Safari (WebKit).
- Found on the way: the browser pane's dev servers hang at start (`uv_cwd` blocked on macOS's
  folder permission for ~/Desktop), so the core and window ran from the shell instead. The
  launch entries `alpha-v2-core` and `alpha-v2-window` are in `../.claude/launch.json` for when
  that permission is given.

Kenil agreed the gate mechanism ("ok makes sense to me", 20:21 UTC); design §5 and §7 now say
it: refused with words while the card waits, the card holding the exact call, the yes letting
that same call through once.
