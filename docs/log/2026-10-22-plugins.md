## Sub-step 3: the registry, the gate adapter, the ClaudeCode provider

- `engine/registry.ts`: a `ToolEntry` (server, name, description, input shape, handler,
  alwaysLoad) and `entry()` to write one; `Registry` finds by model-facing name, lists names,
  `call(name, input)` runs a handler directly (Alpha's own loop, sub-step 4), and `servers()`
  builds the Agent SDK's in-process servers from the same entries, one per server name, Alpha's
  own loaded whole. `tools.ts` writes its tools as entries (`worldTools` returns them);
  `ConnectorService.entries()` does the same per connector, and `servers()` goes through the
  registry. Neither imports the Agent SDK now.
- `engine/gate.ts`: `Gatekeeper`, the one place a call is journaled and put to the gates:
  `before(tool, input, {callId, subagent})` (the `call` line, the live "doing", a connector tool's
  preview and key, a world tool's effect, removals and the person's own entries, a route's own
  tool let through), `network(host)` (the sandbox's ask), `after({callId, ok, ms, error})` (the
  `called` line; the hosts whose reach waits, for the model's own eyes). Its words come from the
  connector or `stepWords`.
- `engine/provider.ts`: `Provider` (name, route, what it can do, `session(spec)`, `ask(system,
  prompt, schema)`), `Session` (send, interrupt, close, events), `SessionEvent` (init, text,
  break, assistant, task, limit, result), `SessionSpec` (where the desk is, the registry, the
  gate, the layers, the file walls, the prompt's shape). `engine/ask.ts` holds the one-question
  ask (moved from `files/reading.ts`; runs and the kit test runner import it from there).
- `engine/claudecode.ts`: `ClaudeCodeProvider`, today's route unchanged: the SDK's options
  built from the spec, its hooks calling the Gatekeeper, `canUseTool` calling the gate for the
  network and the desk's file walls, the SDK's messages translated to session events; `ask`
  through the SDK with the route's env. A scripted `query` still goes in for tests.
- `desk.ts` speaks to a `Provider` only: it builds the registry (`registry()`), owns the
  Gatekeeper, gives the session its layers and file walls, and handles session events (the
  rate-limit retry, background work's own turns, the reply's streaming, the result line) as
  before. `main.ts` makes one `ClaudeCodeProvider` and derives the reader's and judging's `ask`
  from it. Nothing changes for the person; the desk tests pass unchanged, and `gate.test.ts`
  drives the adapter and the registry with no SDK in between.

## Sub-step 4: Alpha's own loop and the ClaudeApi provider

- `engine/loop.ts`: `OwnLoop`, a `Session` over one `chat` call (the whole conversation in,
  text streamed out, the final content with its stop reason): the start and turn layers go in
  beside the person's words as a second text block; every registry entry's schema goes as a tool
  (`toolsOf`, zod to JSON schema); each `tool_use` goes through `Gatekeeper.before`, then
  `Registry.call`, then `Gatekeeper.after`, and back as its `tool_result` (a refusal or a card's
  wait as an error result the model reads); rounds until `end_turn`; `loop_rounds_per_turn`
  (limits.yaml, 60) is the wall against a model that never finishes; a stop aborts the request and
  answers what was started so the kept conversation stays whole; `Limited` becomes the desk's
  `limit` line. The session's messages are kept in the world (`desk_messages`, migration 18;
  `World.messages/keepMessage/clearMessages`) and come back when the session resumes under the
  same tools; a fresh session starts them again.
- `engine/claudeapi.ts`: `ClaudeApiProvider` (route `key`; can: no shell, files, web or
  subagents; structured yes) through `@anthropic-ai/sdk` 1.1.0: `messages.stream` with the key
  read from the Keychain at each request, a rate limit as `Limited` with `retry-after`, a bad key
  as a refusal in words; `ask` with `output_config.format` json_schema. A scripted `chat` goes in
  for tests.
- The route grows a third name, `api` (`ModelRoute`, `/api/model`, the views): the key through
  Alpha's own loop; `key` stays Claude Code with the key. `main.ts` makes both providers and the
  desk picks by the route when a session opens (`DeskOptions.provider` may be a function); the
